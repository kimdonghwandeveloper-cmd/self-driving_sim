## 1. 배경과 사용자 요청

4-5 경로 선택 화면은 저장된 여수 스냅샷(약 1.3 × 1.2 km)의 도로 중심선만 선으로 그린다. 사용자는 이 화면을 보고 다음을 요청했다(2026-11-07).

- **도로 자료는 OSM을 유지한다.** 네이버 지도 API로 바꾸는 안은 채택하지 않았다. Rust를 쓴다는 사실 자체는 불가 사유로 보지 않고,
  아래 세 기준으로 판단했다. 이번에 네이버 문서·약관을 확인하지 않았으므로 **확인하지 않은 항목은 "미확인"**이다.

  | 기준 | 판단 | 근거 상태 |
  | --- | --- | --- |
  | 도로 연결 데이터(노드·교차로 관계)를 제공하는가 | 코스 생성에는 노드 ID로 이어진 도로망이 필요하다. 지도 표시·경로 안내 API가 이런 원자료를 내주는지 확인하지 못했다 | **미확인** |
  | 화면 연동: 데스크톱 앱에 지도를 어떻게 띄우는가 | 웹(JS)·모바일 SDK 중심이면 웹 화면 구성 요소가 필요하다. 가능은 하지만 이 프로젝트는 Rust 단독 구성을 선택했다(언어 자체의 제약이 아니라 프로젝트 선택) | 제공 형태 **미확인** |
  | 저장·가공 조건: 약관이 받은 자료의 저장·변형(코스 생성)을 허용하는가 | 코스 재현을 위해 자료를 저장하고 변형해야 한다 | **미확인** |

  OSM은 세 기준 모두를 공개 자료와 ODbL로 확인할 수 있어 유지한다.
- **시뮬레이터 메인 화면을 만든다.** "맵 생성하기" 같은 탭에서 지도로 경로를 그리게 한다.
- **실제 전국 지도를 배경으로 보여 준다.** 파란 배경에 길만 있는 지금 화면보다 경로를 그리기 쉽게 한다.
- 배경 지도 출처는 **OSM 공식 타일 서버**(tile.openstreetmap.org)로 사용자가 골랐다.

## 3. 제안 항목

### 4-5a. 메인 화면

- [ ] 앱 상태 `MainMenu`를 더한다. 인자 없이 실행하면 메인 화면부터 시작한다.
- [ ] 메뉴:
  - **주행하기**: 개발 코스(training·calibration) 또는 저장된 경로 파일(`cache/routes/*.toml`, 이름·시각·길이 목록)을 골라 주행한다.
  - **맵 생성하기**: 경로 선택 화면(4-5b)으로 간다.
  - **종료**
- [ ] 주행 중 메인 화면으로 돌아가기(예: `Esc` → 확인)를 넣는다. 상태 수명과 초기화 대상은 다음과 같다(Codex 검토 반영).
  - 엔티티: 주행 화면과 선택 화면의 카메라·조명·차량·코스·격자·HUD·출처 패널을 각 상태 수명에 묶는다(나가면 지움). 엔티티·렌더 자원이 중복되지 않는지 확인한다.
  - 초기화하는 리소스: `Vehicle`, `VehicleMotion`, `DriverInput`, 장치 입력 프레임·`InputStatus`, 피드백, `VehicleContact`, `TrainingLog`, 보정 시험·기록 상태, `ActiveView`.
  - 미소비 메시지(`ControlRequest`, `ResetCourseRequest`, `CourseResetDone`, `CollisionEvent` 등)를 비운다. 전환 때 누른 Enter·Esc·버튼 입력이 다음 화면으로 넘어가지 않게 한다.
  - 초기화하지 않는 것: 입력 바인딩·차량 설정 등 사용자 설정.
  - 진행 중인 `FetchJob` 결과는 세대 토큰으로 묶어 이전 화면에 적용하지 않는다. 받는 중에 메뉴로 갔다가 다시 들어와도 동시 작업 제한과 진행 표시가 맞아야 한다.
  - 교육 경과 시간은 새 주행 기준으로 다시 잰다. 앱 시작 후 경과 시간과 구분한다.
- [ ] 기존 명령줄 실행(`--course`, `--smoke-test`, `--capture-views`, `--pick-route`)은 메인 화면을 건너뛰고 지금처럼 동작한다(자동 검증 유지).
- **완료 기준(회귀 테스트):**
  - 메뉴 → 저장 경로 → 주행 → 메뉴 → 선택 → 다른 경로 → 주행을 3회 이상 반복한다.
  - 키를 누른 채 복귀, 비상 정지·충돌·보정 시험 진행 중 복귀, 저장 실패·잘못된 경로 파일·다운로드 중 복귀를 각각 시험한다.
  - 확인 항목: 엔티티 수가 일정한지, 차량 상태·기록이 초기화되는지, 출처 패널이 하나인지, 선택한 코스가 맞는지, 메시지가 남지 않는지.

### 4-5b. 전국 배경 지도와 지역 고르기

- [ ] 경로 선택 화면 배경에 OSM 표준 래스터 타일을 깐다. 화면 좌표는 웹 메르카토르(EPSG:3857)다. 확대 수준은 전국(약 z6)부터 거리(z18)까지 쓰며, 화면에 보이는 타일만 받는다.
- [ ] 받은 도로 그래프(노드 ID 스냅샷)를 타일 위에 겹쳐 그린다. 코스 계산은 지금처럼 지역 평면 좌표로 한다. 웹 메르카토르 ↔ 위경도 ↔ 지역 평면 변환을 테스트한다.
- [ ] 흐름:
  1. 전국 지도에서 지역을 찾는다.
  2. 확대해서 "이 지역 도로 받기"를 누르면, 화면 가운데 1.5 × 1.5 km를 4-4 `FetchJob`으로 받는다. 대한민국 범위·2 km·20 MB 검사는 그대로다.
  3. 받은 도로 위에 점을 찍는다(4-5 기능).
  4. 주행을 시작한다.
- [ ] 이미 받은 범위(캐시 세대)는 지도에 테두리로 표시하고 다시 고를 수 있게 한다.
- [ ] 처음 보기: 전국 보기로 시작한다. 지역을 받으면 그 범위에, 경로를 처음 계산하면 경로 전체에 **한 번씩만** 맞춘다. 그 뒤 사용자가 화면을 움직이면 자동으로 다시 맞추지 않는다(화면을 빼앗지 않음).
- [ ] 맞춤 보기 버튼 세 가지: **전국**(`K`), **받은 지역**(`G`), **경로**(`F`).
- [ ] 타일 받기 관리(Codex 검토 반영):
  - 같은 타일 요청은 하나로 합치고, 화면이 바뀌어 더는 보이지 않는 대기 요청은 버린다.
  - 응답 크기 상한과 PNG 형식·256 × 256 치수를 검사한다.
  - 메모리·디스크 캐시 예산을 둔다(값은 구현 때 임시값으로 정함).
  - 실패한 타일은 다시 시도 간격을 늘린다. 403·429에서 매 프레임 다시 요청하지 않는다.
  - `304 Not Modified`면 기존 이미지를 유지하고 만료 정보만 갱신한다. `Cache-Control`/`Expires`, `ETag`/`Last-Modified`를 함께 저장한다.
- **완료 기준:**
  - 타일 좌표 계산·필요 타일 목록을 테스트로 확인한다.
  - 캐시 동작을 테스트로 확인한다: 만료, 304, 손상 캐시, 받기 실패, 정상 재방문.
  - 웹 메르카토르 ↔ 위경도 ↔ 지역 평면 왕복 오차를 여러 확대 수준·창 크기·DPI에서 확인한다. 기준은 예: 화면 1 px 이하, 지역 좌표 0.1 m 이하. 기준값은 구현 때 확정한다.
  - 오프라인이거나 타일을 받지 못하면 회색 칸으로 표시하고, 도로 그래프·경로 계산·저장·주행은 그대로 동작한다(회귀 테스트).
  - 사람이 전국 → 여수 확대 → 도로 받기 → 경로 찍기 → 주행을 확인한다.

## 4. OSM 타일 사용 정책 준수

출처: <https://operations.osmfoundation.org/policies/tiles/> (2026-11-07 확인, 정책에 개정 날짜 표시 없음). 정책은 언제든 바뀔 수 있으므로 구현할 때 다시 확인한다.

| 정책 요구 | 구현 방안 |
| --- | --- |
| URL은 `https://tile.openstreetmap.org/{z}/{x}/{y}.png`만 쓰고, 하드코딩을 피하라고 권장 | 설정 파일에 URL을 두고 기본값을 이 주소로 한다. HTTP·다른 하위 도메인은 쓰지 않는다. URL을 다른 제공자로 바꾸면 그 제공자의 약관을 따로 확인해야 하며, 이 표의 대응이 그대로 맞는다고 보지 않는다. |
| 앱을 밝히는 고유하고 고정된 User-Agent(연락처는 선택, 공개 연락처는 권장). 라이브러리 기본 User-Agent 금지. 데스크톱 앱은 Referer 불필요 | 기존 `self-driving-sim-dev/0.1`을 쓴다. 개인 이메일은 넣지 않는다(프로젝트 규칙). 공개 연락처(저장소 URL 등)를 넣을지는 사용자에게 확인한다. |
| 캐시 헤더(Cache-Control, Expires, ETag)를 따르고, 못 읽으면 최소 7일. 만료 후에는 조건부 요청 | 타일 디스크 캐시(`cache/tiles/`, 저장소 제외)에 헤더와 함께 저장한다. 만료되면 `If-None-Match`/`If-Modified-Since`로 다시 묻는다. `no-cache` 요청 헤더는 보내지 않는다. |
| 대량 받기·미리받기·오프라인용 받기 금지(보이는 타일만, 브라우저 수준의 짧은 앞당김만 허용) | 화면에 보이는 타일만 요청한다. 오프라인 받기 버튼이나 백그라운드 미리받기는 만들지 않는다. 화면 밖 한 칸 앞당김도 1차 판에서는 하지 않는다. |
| 오프라인용 받기 금지(정책의 "offline" 금지는 미리 일괄로 받아 두는 기능을 막는 것이다. 정상적으로 본 타일의 캐시를 다시 쓰는 것과는 다르다) | 오프라인 받기 기능은 만들지 않는다. 네트워크가 없으면 정상적으로 보며 캐시해 둔 타일만 보여 주고, 없으면 회색 칸으로 둔다. 코스 재현은 타일과 무관하다(노드 ID 스냅샷만 쓴다). |
| 지도 위에 출처 표기를 분명히(보통 오른쪽 아래). UI 아래로 숨기거나 끄기·화면 밖 금지 | 지도 화면 오른쪽 아래에 "© OpenStreetMap contributors"를 늘 표시한다. 다른 UI가 가리지 않게 한다. |
| 사용량이 서비스를 해치면 예고 없이 차단, SLA 없음 | 동시 요청 수를 적게 제한하고(예: 2개, 임시값) 실패하면 빈 칸으로 둔다. 차단되면 배경 없이 동작한다. 사용량이 늘면 자체 타일 서버 등 대안을 검토한다. |
| 자동 스캔·헤드리스 봇 금지 | 자동 검증(`--smoke-test`·`--capture-views`)과 시험에서는 **타일을 받지 않는다**. 명령줄 플래그뿐 아니라 시험용 전송 수단·설정으로도 외부 요청이 불가능하게 만든다. 가짜 전송 수단이나 로컬 시험 서버만 쓴다. |

## 5. 구현 메모

- HTTP는 4-4에서 고정한 `ureq =3.5.1`을 재사용한다. PNG 디코딩은 Bevy 이미지 기능(이미 포함된 png)을 쓴다. 새 크레이트는 필요 없을 것으로 예상한다(구현 때 확인).
- 타일은 3D 직교 카메라 아래의 평면 메시에 텍스처로 붙이거나 UI 이미지로 깐다. 어느 쪽이 좌표 맞추기와 기존 3D 선 그리기와 잘 맞는지는 구현 때 정한다.
- 4-5의 `PickerModel`·경로 계산·저장·주행 전환 테스트는 그대로 재사용한다.
- 순서: 4-5a(타일 없는 메뉴·상태 수명)를 먼저 구현·검증한 뒤 4-5b(배경 지도)를 붙인다. 전환 결함과 좌표·통신 결함을 구별하기 쉽게 하려는 것이다. 각 단계마다 Codex 검증을 받고, 마지막 통합 검증은 4-6에서 한다.

## 7. Codex 검토 결과 요약(1판)

1. 배경 타일과 벡터 코스를 분리하는 것은 적절하다. 타일이 실패해도 경로 계산·저장이 막히지 않는 회귀 테스트가 필요하다. → 4-5b 완료 기준에 반영
2. 타일 정책 대조는 타당하다. 반영한 내용:
   - "offline 금지"는 미리 일괄로 받아 두는 기능을 막는 것이라고 문구를 정리했다.
   - URL을 바꾸면 다른 제공자의 약관을 따로 확인한다.
   - 공개 연락처는 권장 사항으로 남겼다.
   → 4절에 반영
3. 메인 화면 복귀 시 초기화 대상, 메시지·입력이 다음 화면으로 넘어가는 것 차단, `FetchJob` 세대 토큰, 교육 경과 시간, 회귀 시나리오를 구체화하라는 의견이다. → 4-5a에 반영
4. 4-5a·4-5b로 나눠 4-6 앞에 두는 순서가 좋다. 메뉴를 먼저 검증한다. → 5절에 반영
5. 다음 보완 제안을 반영했다. → 4-5b, 4절, 1절에 반영
   - 타일 중복·폐기·검사·예산·재시도, 304·캐시 헤더 처리
   - 좌표 왕복 오차 기준, 맞춤 보기가 화면을 빼앗지 않게 하기
   - 시험에서 외부 요청을 원천적으로 막기
   - 네이버를 쓰지 않는 사유 문구를 명확히 하기
