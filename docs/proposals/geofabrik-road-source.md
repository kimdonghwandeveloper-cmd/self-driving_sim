# 제안: Geofabrik 한국 전체 OSM 자료를 도로 원자료 공급원으로 도입

- 상태: **토론 초안 2판** (PLAN 변경·다운로드·구현 전, 사용자 확인 대기)
- 작성일: 2026-11-07
- 범위: 경로·교차로·코스 생성에 쓰는 **도로 벡터 원자료**의 공급원. 경로 선택 화면의 배경 지도(타일, 4-5b 제안)는 별개로 유지한다.
- 전제 코드: 노드 ID 보존 그래프(`osm_graph.rs`), 경로 계획(`route_plan.rs`, 4-3), 불변 캐시 세대(`map_fetch.rs`, 4-4).
  4-3·4-4는 작업 브랜치에서 Codex `continue`를 받았고 main에는 아직 병합되지 않았다.

## 1. 배경과 목표

- 지금은 지역마다 Overpass에 `out body geom`을 요청해 스냅샷을 만든다. 요청 지연, 실패 재시도(429·504), 서버 부하 문제가 있다.
- Geofabrik는 한국 전체 `.osm.pbf`를 매일 갱신해 제공한다(2026-11-05 파일 291,019,374 bytes, 약 277.5 MiB).
- 목표: 한 번 받은 전국 파일에서 사용자가 고른 지역의 도로만 잘라, **기존 노드 ID·연결·태그를 그대로 보존한 지역 스냅샷**을 만든다.
  그 뒤의 경로 탐색·교차로·코스 생성·재생은 지금 코드를 그대로 쓴다.
- 전국 자료 도입이 **전국 모든 도로의 코스 생성 지원을 뜻하지 않는다**. 현재 지원·거부 조건(§5.2)을 그대로 유지한다.

## 2. PBF 읽기, 메모리, 인덱스·캐시

### 2.1 라이브러리

| 후보 | 버전·라이선스 | 판단 |
| --- | --- | --- |
| `osmpbf` | 0.3.8, MIT OR Apache-2.0, 순수 Rust(기본 `rust-zlib`), rust-version 1.88 | **채택 후보.** PBF 읽기, 블록 단위 병렬 처리(`par_map_reduce`), 요소 종류별 걸러 읽기 지원. 읽기 전용 |
| `osmpbfreader` | 0.19.1 | 대안. 라이선스 미확인 |
| `osmium` 등 외부 도구 | — | 프로젝트의 Rust 단독 구성 선택과 맞지 않아 런타임 의존으로는 쓰지 않는다 |

PBF에서 way는 노드 ID 목록만 갖고 좌표는 노드 블록에 따로 있다. 따라서 좌표를 얻으려면 노드와 way를 모두 읽어야 한다.

### 2.2 두 번 읽기와 메모리 범위 (정정)

두 번 읽기는 다음과 같다.

1. **1차(way):** 전국의 way 중 허용 `highway`만 골라 way ID·태그·노드 ID 목록을 모은다.
2. **2차(node):** 1차에서 모은 노드 ID의 좌표만 읽는다.

**주의:** 영역 판별(§3.1)은 좌표가 있어야 할 수 있으므로 2차가 끝나기 전에는 할 수 없다. 즉 1차 결과는 **전국의 허용 도로 전체**이고,
2차가 끝날 때까지 이를 메모리에 보유한다. 이 방식은 "지역 자료만 읽는 방식"이 아니다. 지역만 읽을 수 있는 것은 §2.3의 인덱스를 만든 뒤다.

보유해야 하는 것(전국 기준):

| 자료 | 내용 | 크기 |
| --- | --- | --- |
| 허용 도로 way | way ID, 태그, 노드 ID 목록 | **미측정** |
| 필요 노드 ID 집합 | 정렬한 `Vec<u64>`(이분 탐색) 또는 해시 집합 | **미측정** |
| 노드 좌표 표 | 노드 ID → 위경도(정수 1e-7° 두 개) | **미측정** |

- 메모리를 줄이는 선택지: 태그를 필요한 키만 남기기, 노드 ID를 정렬 `Vec`로 두기, 좌표를 정수로 저장하기. 효과는 측정해 보고 판단한다.
- 블록 단위 병렬 처리를 쓰면 처리 중 블록 버퍼만큼 메모리가 더 든다.
- **G-1에서 최대 메모리(프로세스 최대 작업 집합)와 단계별 시간을 측정해 기록한다.** 측정 전에는 수치를 약속하지 않는다.

### 2.3 인덱스 구조 비교 (G-2에서 결정)

인덱스는 버전마다 한 번 만들고, 이후 지역을 고를 때는 필요한 칸만 읽는다. 두 구조를 비교한다.

| 구조 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 칸마다 way 전체 복제** | 격자 칸 파일에 그 칸에 걸치는 way의 태그·노드·좌표를 통째로 저장 | 조회가 단순(칸 파일만 읽음) | 긴 도로(고속도로·국도)가 지나는 칸 수만큼 **중복 저장**. 크기 예측 어려움 |
| **B. 칸 → way ID, way ID → 도로·노드** | 칸 파일에는 way ID 목록만, 도로 본체(태그·노드 ID·좌표)는 way ID로 찾는 별도 저장소에 한 번만 저장 | 중복 없음. 크기가 도로 총량에 비례 | 조회가 두 단계. 본체 저장소의 임의 접근(오프셋 표 등) 설계 필요 |

- 기본안은 **B**로 두되, G-2에서 두 구조의 크기·조회 시간을 실제로 재서 정한다.
- 어느 구조든 §3.2 검증에 쓰도록 **전국 기준 노드별 이웃 노드 ID 목록**(또는 그것을 다시 계산할 수 있는 정보)을 함께 둔다.
- 격자 크기(예: 0.05°)도 측정 후 정한다.

### 2.4 디스크 사용량 (추정)

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 전국 PBF | 291,019,374 bytes | Geofabrik 목록의 2026-11-05 파일. **확인값** |
| 인덱스 | 미측정 | 구조 A/B에 따라 크게 다름 |
| 지역 스냅샷 | 지역당 MB 단위로 **추정** | 현재 Overpass 캐시 크기와 비슷할 것으로 봄 |
| 이전 세대 하나 포함 합계 | **1 GB 이하로 추정** | 보장값 아님. G-1·G-2 측정 후 갱신 |

- 현재 C: 여유는 약 13 GB(2026-11-07 기준).
- 전국 PBF와 인덱스는 `/cache/` 아래에 두고 git에 올리지 않는다.

## 3. 추출 규칙과 경계 연결 검증

### 3.1 way 선택 규칙

선택 영역 R = 사용자 영역 + 여유 폭 m(스냅 상한 100 m 이상, 값은 G-1에서 정함).

way를 다음 중 **하나라도** 만족하면 선택한다.

1. 노드 하나라도 R 안에 있다.
2. **연속한 두 노드 사이 선분이 R과 교차한다.** 양 끝 노드가 모두 R 밖이어도 선분이 R을 통과하면 선택한다(사각형-선분 교차 검사).

선택한 way는 **노드를 모두 보존**한다(R 밖 노드를 자르지 않음). 노드 ID·순서·태그를 바꾸지 않는다.

> 참고: Overpass `way(bbox)`도 같은 의미인지는 확인하지 않았다. G-1의 여수 비교에서 가로지르는 way가 양쪽에 똑같이 있는지 확인한다.

### 3.2 경계 연결 검증 (G-1부터 적용)

way를 R과 한 단계 이웃까지 넣어도 연결이 완전하다고 보장할 수 없다. 영역 밖에서 이어지는 도로가 경계 노드에서 빠질 수 있고,
차수만 같고 실제로 붙은 도로가 다를 수도 있다. 그래서 **추출 결과를 전국 자료와 대조**해 확인한다.

- 대조 대상 노드: 경로가 지나는 노드, 그리고 경로가 지나는 교차로의 팔·곁가지 형상을 만드는 데 쓰는 노드.
  - 교차로 형상(4-2)은 경로 밖의 팔(곁가지 stub)까지 쓰므로, 경로 노드만으로는 부족하다.
- 대조 방법:
  1. **차수 대조:** 지역 자료에서 센 차수와 전국 자료에서 센 차수(허용 도로 기준)가 같은지.
  2. **이웃 노드 ID 대조:** 차수가 같아도 연결이 다를 수 있으므로, 노드마다 **이웃 노드 ID 집합**(어느 way의 어느 이웃인지 포함)이 전국 자료와 같은지.
  3. **팔·곁가지 길이 충분성:** 교차로 형상 생성에 필요한 팔 길이(현재 교차로 설정의 절단 길이 등)만큼 각 팔의 노드가 지역 자료 안에 이어져 있는지.
- 하나라도 맞지 않으면 그 지역 스냅샷으로는 **코스 생성을 거부**하고, 어느 노드가 어떤 이유로 부족한지 보여 준다.
  좌표가 가깝다는 이유로 연결을 추정하거나 임의로 이어 붙이지 않는다.
- 부족할 때 할 수 있는 조치는 여유 폭 m을 늘려 다시 추출하는 것뿐이다(자동 재시도 여부는 G-1 결과를 보고 정한다).

### 3.3 G-1에서의 전국 대조 자료

G-1에는 인덱스가 없으므로, §2.2의 두 번 읽기 중 전국 허용 도로를 보유한 상태에서 **같은 실행 안에서** 전국 기준 차수·이웃 노드 ID를 계산해 대조한다.
G-2부터는 인덱스에 저장한 전국 이웃 정보로 대조한다. 두 결과가 같은지도 G-2 검증 항목이다.

### 3.4 기존 규칙 유지

- 좌표 누락, 노드 2개 미만 way, 범위 밖 좌표는 지금처럼 오류.
- 도로 연결은 같은 노드 ID로만 판단.

## 4. 파일 식별·무결성·버전 관리

### 4.1 두 가지를 구분한다

| 목적 | 방법 | 증명하는 것 | 증명하지 못하는 것 |
| --- | --- | --- | --- |
| **버전 식별** | 받은 파일에서 직접 계산한 해시(예: SHA-256 또는 MD5), PBF 머리부의 복제 시각·순번 | "어떤 파일인지" 구별, 저장 코스가 어느 원본에서 왔는지 기록 | 파일이 **제대로 받아졌는지**(잘린·손상된 파일도 해시는 나옴) |
| **다운로드 무결성** | §4.2의 검사들 | 전송이 끝까지 됐고, 제공자가 공개한 파일과 같으며, PBF로 읽힘 | — |

### 4.2 무결성 검사 단계

1. **전송 완료 검사:** HTTP 상태 200, `Content-Length`가 있으면 받은 바이트 수와 일치. 연결이 중간에 끊기면 실패.
2. **제공 체크섬 대조:**
   - Geofabrik는 날짜가 붙은 파일(`south-korea-YYMMDD.osm.pbf`)에 `.md5`를 제공한다. 목록에서 `latest` 파일의 `.md5`는 보지 못했다.
   - 따라서 기본안은 **날짜 붙은 파일과 그 `.md5`를 함께 받아 대조**하는 것이다. 어느 날짜 파일을 받을지 정하는 방법(디렉터리 목록 해석, `index-v1.json`, `state.txt` 등)은 G-3에서 확인한다.
   - 제공 체크섬을 얻지 못하면: **무결성 미확인**으로 표시하고, 사용자가 명시적으로 허용할 때만 사용한다(기본은 거부).
3. **PBF 파싱 검사:** 머리부 블록을 읽고, 모든 블록을 끝까지 압축 해제·해석할 수 있어야 한다. 실패하면 거부.
4. **머리부 정보 처리:**
   - 복제 시각(`osmosis_replication_timestamp`)·순번이 있으면 세대 메타에 기록.
   - **없으면:** 파일 자체는 거부하지 않되, 버전 식별은 파일 해시 + 받은 시각 + 원본 URL로 하고, 메타에 "머리부 시각 없음"을 기록한다.
     데이터 시각을 화면에 보여 줄 때도 "미확인"으로 표시한다.
   - 머리부의 범위(bbox)가 한국 범위와 크게 다르면 거부.

### 4.3 저장과 실패 시 보존

- `.part` 파일로 받는다 → §4.2 검사 → 인덱스 생성(G-2 이후) → 모두 성공했을 때만 세대 폴더로 옮기고 `latest.toml`을 바꾼다.
- 어느 단계에서 실패해도 **기존 세대는 그대로**다. 실패한 `.part`는 다음 시도 때 지운다(사용자 파일이 아니라 앱이 만든 임시 파일).
- 세대 폴더: `cache/geofabrik/south-korea/<UTC 시각>-<해시 앞자리>/{source.osm.pbf, meta.toml, index/...}`.

### 4.4 저장 코스의 재현

- 저장한 경로 파일(`route-v1`)은 지금처럼 **지역 스냅샷 세대**를 가리킨다.
- 지역 스냅샷 `meta.toml`에 출처(`geofabrik` / `overpass`), 원본 PBF의 해시·머리부 시각·URL, 추출 규칙 버전, 여유 폭 m을 기록한다.
- Geofabrik는 오래된 날짜 파일을 "after a while" 삭제한다고 안내한다. 그래서 전국 파일을 다시 받을 수 없어도
  **작은 지역 스냅샷만으로 같은 코스를 다시 만들 수 있게** 지역 스냅샷을 불변으로 보존한다. 전국 세대를 지워도 저장 코스는 재생된다.

### 4.5 갱신

- 매일 갱신되지만 **자동으로 받지 않는다.** 사용자가 요청할 때만 받는다.
- 변경분(`.osc.gz`) 적용 갱신은 이번 범위에서 제외한다.

## 5. Overpass와의 관계, 지원 조건

### 5.1 병행

- **병행을 추천한다.** 검증이 끝나면 Geofabrik를 기본으로 쓰고, Overpass는 전국 파일이 없거나 최신 자료가 필요한 작은 지역에 쓰는 보조 수단으로 둔다.
- 두 출처 모두 같은 지역 스냅샷 형식(현재 `graph.osm.json` + `meta.toml` 세대)으로 저장해, 그 뒤 처리를 같게 한다.
- `--offline`과 자동 시험의 외부 요청 금지는 유지한다. 자동 시험은 저장소에 둔 작은 시험 자료만 쓴다.

### 5.2 지원·거부 조건 유지

- 허용 도로 종류와 최소 폭 규칙
- 한국 범위(위도 33.0–38.7, 경도 124.5–132.0)
- 경로 범위 1500 × 1500 m, 스냅 100 m, 경로 길이 2000 m 상한
- 교차로 형상 검사(4-2)
- 추가: §3.2 경계 연결 검증 실패 시 거부

## 6. ODbL 출처 표기와 배포 조건

Geofabrik 다운로드 페이지 문구: "licensed under the Open Database License 1.0 … you have to acknowledge OpenStreetMap as the data source. Derived databases have to retain the same license."

- 화면: 경로 선택·주행 화면에 "© OpenStreetMap contributors"와 ODbL 링크 표시(현재 방식 유지).
- 파생 데이터베이스(인덱스, 지역 스냅샷)를 배포할 때는 ODbL을 유지하고 출처를 표기한다.
- 전국 PBF와 인덱스는 git에 올리지 않는다. 저장소에 넣는 시험 자료는 출처·라이선스 문구를 함께 둔다.
- 공개 파일에는 `user`·`uid`·`changeset`이 없다("missing … since May 3, 2018").
- 다운로드 예절: 확인한 페이지에는 요청 제한이나 User-Agent 규정이 없었다. 그래도 일반 UA `self-driving-sim-dev/0.1`, 한 번에 하나, 사용자 요청 시에만 받는다.
- 이 절은 공개 문구 요약이며 법률 검토가 아니다.

G-1 검증 항목:

- 기존 여수 Overpass 스냅샷과 비교: way·노드 ID 집합 겹침. 자료 날짜 차이로 생긴 차이는 결함과 따로 보고.
- 영역을 가로지르는 way(양 끝 노드가 영역 밖)가 포함되는지.
- 교차로 4곳(5143354386 포함) 일치, 같은 점으로 계산한 경로의 노드 순서 일치.
- 경계 연결 검증: 정상 지역은 통과, 여유 폭을 일부러 줄인 경우는 거부되는지.
- 코스 생성·시험 주행 회귀.
- **최대 메모리, 단계별 시간, 지역 스냅샷 크기 측정·기록.**

예상 규모(대략): G-1 새 모듈 하나 400~700줄, G-2 500줄 안팎, G-3 300줄 안팎, G-4 300줄 안팎. 측정 결과에 따라 달라질 수 있다.

메뉴(4-5a)·배경 지도(4-5b)와의 순서: G-1은 CLI와 모듈 하나라 서로 영향이 없다. 순서는 사용자가 정한다.

## 8. 미확인 사항

- 시험용 작은 PBF를 만드는 방법(`osmpbf`는 읽기 전용이므로 시험 코드 안의 간단한 작성기가 필요할 수 있음).
- Geofabrik 파일이 종류별·ID순으로 정렬되어 있는지(두 번 읽기 최적화 가능 여부).
- 한국 허용 도로 way·노드 수, 최대 메모리, 인덱스 크기.
- 날짜 붙은 파일과 `.md5`를 안정적으로 찾는 방법, `latest` 파일의 체크섬 제공 여부.
- Overpass `way(bbox)`가 가로지르는 way를 포함하는지.
- Geofabrik imprint와 다운로드 서버 이용 조건, `osmpbfreader` 라이선스.
