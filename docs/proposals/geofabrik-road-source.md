# 제안: Geofabrik 한국 전체 OSM 자료를 도로 원자료 공급원으로 도입

- 상태: **토론 초안 5판** (PLAN 변경·다운로드·구현 전, 사용자 확인 대기)
- 작성일: 2026-11-07
- 범위: 경로·교차로·코스 생성에 쓰는 **도로 벡터 원자료**의 공급원. 경로 선택 화면의 배경 지도(타일, 4-5b 제안)는 별개로 유지한다.
- 전제 코드: 노드 ID 보존 그래프(`osm_graph.rs`), 경로 계획(`route_plan.rs`, 4-3), 불변 캐시 세대(`map_fetch.rs`, 4-4).
  4-3·4-4는 작업 브랜치에서 Codex `continue`를 받았고 main에는 아직 병합되지 않았다.

## 1. 배경과 목표

- 지금은 지역마다 Overpass에 `out body geom`을 요청해 스냅샷을 만든다. 요청 지연, 실패 재시도(429·504), 서버 부하 문제가 있다.
- Geofabrik는 한국 전체 `.osm.pbf`를 매일 갱신해 제공한다(2026-11-05 파일 291,019,374 bytes, 약 277.5 MiB).
- 목표: 한 번 받은 전국 파일에서 사용자가 고른 지역의 도로만 잘라, **기존 노드 ID·연결·태그를 그대로 보존한 지역 스냅샷**을 만든다.
  경로 탐색 알고리즘·교차로 형상·코스 생성은 그대로 두고, 스냅샷을 읽는 부분과 검증은 바꾼다(변경 범위 구분은 §4.7).
- 전국 자료 도입이 **전국 모든 도로의 코스 생성 지원을 뜻하지 않는다**. 현재 지원·거부 조건(§5.2)을 그대로 유지한다.

## 2. PBF 읽기, 메모리, 인덱스·캐시

### 2.1 라이브러리

| 후보 | 버전·라이선스 | 판단 |
| --- | --- | --- |
| `osmpbf` | 0.3.8, MIT OR Apache-2.0, 순수 Rust(기본 `rust-zlib`), rust-version 1.88 | **채택 후보.** PBF 읽기, 블록 단위 병렬 처리(`par_map_reduce`), 요소 종류별 걸러 읽기 지원. 읽기 전용 |
| `osmpbfreader` | 0.19.1 | 대안. 라이선스 미확인 |
| `osmium` 등 외부 도구 | — | 프로젝트의 Rust 단독 구성 선택과 맞지 않아 런타임 의존으로는 쓰지 않는다 |

PBF에서 way는 노드 ID 목록만 갖고 좌표는 노드 블록에 따로 있다. 따라서 좌표를 얻으려면 노드와 way를 모두 읽어야 한다.

### 2.2 두 번 읽기와 메모리 범위 (정정)

두 번 읽기는 다음과 같다.

1. **1차(way):** 전국의 way 중 허용 `highway`만 골라 way ID·태그·노드 ID 목록을 모은다.
2. **2차(node):** 1차에서 모은 노드 ID의 좌표만 읽는다.

**주의:** 영역 판별(§3.1)은 좌표가 있어야 할 수 있으므로 2차가 끝나기 전에는 할 수 없다. 즉 1차 결과는 **전국의 허용 도로 전체**이고,
2차가 끝날 때까지 이를 메모리에 보유한다. 이 방식은 "지역 자료만 읽는 방식"이 아니다. 지역만 읽을 수 있는 것은 §2.3의 인덱스를 만든 뒤다.

보유해야 하는 것(전국 기준):

| 자료 | 내용 | 크기 |
| --- | --- | --- |
| 허용 도로 way | way ID, 태그, 노드 ID 목록 | **미측정** |
| 필요 노드 ID 집합 | 정렬한 `Vec<u64>`(이분 탐색) 또는 해시 집합 | **미측정** |
| 노드 좌표 표 | 노드 ID → 위경도(정수 1e-7° 두 개) | **미측정** |

- 메모리를 줄이는 선택지: 태그를 필요한 키만 남기기, 노드 ID를 정렬 `Vec`로 두기, 좌표를 정수로 저장하기. 효과는 측정해 보고 판단한다.
- 블록 단위 병렬 처리를 쓰면 처리 중 블록 버퍼만큼 메모리가 더 든다.
- **G-1에서 최대 메모리(프로세스 최대 작업 집합)와 단계별 시간을 측정해 기록한다.** 측정 전에는 수치를 약속하지 않는다.

### 2.3 인덱스 구조 비교 (G-2에서 결정)

인덱스는 버전마다 한 번 만들고, 이후 지역을 고를 때는 필요한 칸만 읽는다. 두 구조를 비교한다.

| 구조 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 칸마다 way 전체 복제** | 격자 칸 파일에 그 칸에 걸치는 way의 태그·노드·좌표를 통째로 저장 | 조회가 단순(칸 파일만 읽음) | 긴 도로(고속도로·국도)가 지나는 칸 수만큼 **중복 저장**. 크기 예측 어려움 |
| **B. 칸 → way ID, way ID → 도로·노드** | 칸 파일에는 way ID 목록만, 도로 본체(태그·노드 ID·좌표)는 way ID로 찾는 별도 저장소에 한 번만 저장 | 중복 없음. 크기가 도로 총량에 비례 | 조회가 두 단계. 본체 저장소의 임의 접근(오프셋 표 등) 설계 필요 |

- 기본안은 **B**로 두되, G-2에서 두 구조의 크기·조회 시간을 실제로 재서 정한다.
- 어느 구조든 §3.2 검증에 쓰도록 **전국 기준 노드별 이웃 노드 ID 목록**(또는 그것을 다시 계산할 수 있는 정보)을 함께 둔다.
- 격자 크기(예: 0.05°)도 측정 후 정한다.

## 3. 추출 규칙과 경계 연결 검증

### 3.1 way 선택 규칙

선택 영역 R = 사용자 영역 + 여유 폭 m(스냅 상한 100 m 이상, 값은 G-1에서 정함).

way를 다음 중 **하나라도** 만족하면 선택한다.

1. 노드 하나라도 R 안에 있다.
2. **연속한 두 노드 사이 선분이 R과 교차한다.** 양 끝 노드가 모두 R 밖이어도 선분이 R을 통과하면 선택한다(사각형-선분 교차 검사).

선택한 way는 **노드를 모두 보존**한다(R 밖 노드를 자르지 않음). 노드 ID·순서·태그를 바꾸지 않는다.

> 참고: Overpass `way(bbox)`도 같은 의미인지는 확인하지 않았다. G-1의 여수 비교에서 가로지르는 way가 양쪽에 똑같이 있는지 확인한다.

### 3.2 경계 연결 검증 (G-1부터 적용)

way를 R과 한 단계 이웃까지 넣어도 연결이 완전하다고 보장할 수 없다. 영역 밖에서 이어지는 도로가 경계 노드에서 빠질 수 있고,
차수만 같고 실제로 붙은 도로가 다를 수도 있다. 그래서 **추출 결과를 전국 자료와 대조**해 확인한다.

- 대조 대상 노드: 경로가 지나는 노드, 그리고 경로가 지나는 교차로의 팔·곁가지 형상을 만드는 데 쓰는 노드.
  - 교차로 형상(4-2)은 경로 밖의 팔(곁가지 stub)까지 쓰므로, 경로 노드만으로는 부족하다.
- 대조 방법:
  1. **차수 대조:** 지역 자료에서 센 차수와 전국 자료에서 센 차수(허용 도로 기준)가 같은지.
  2. **이웃 노드 ID 대조:** 차수가 같아도 연결이 다를 수 있으므로, 노드마다 **이웃 노드 ID 집합**(어느 way의 어느 이웃인지 포함)이 전국 자료와 같은지.
  3. **팔·곁가지 길이 충분성:** 교차로 형상 생성에 필요한 팔 길이(현재 교차로 설정의 절단 길이 등)만큼 각 팔의 노드가 지역 자료 안에 이어져 있는지.
- 하나라도 맞지 않으면 그 지역 스냅샷으로는 **코스 생성을 거부**하고, 어느 노드가 어떤 이유로 부족한지 보여 준다.
  좌표가 가깝다는 이유로 연결을 추정하거나 임의로 이어 붙이지 않는다.
- 부족할 때 할 수 있는 조치는 여유 폭 m을 늘려 다시 추출하는 것뿐이다(자동 재시도 여부는 G-1 결과를 보고 정한다).

### 3.3 G-1에서의 전국 대조 자료

G-1에는 인덱스가 없으므로, §2.2의 두 번 읽기 중 전국 허용 도로를 보유한 상태에서 **같은 실행 안에서** 전국 기준 차수·이웃 노드 ID를 계산해 대조한다.
G-2부터는 인덱스에 저장한 전국 이웃 정보로 대조한다. 두 결과가 같은지도 G-2 검증 항목이다.

### 3.4 기존 규칙 유지

- 좌표 누락, 노드 2개 미만 way, 범위 밖 좌표는 지금처럼 오류.
- 도로 연결은 같은 노드 ID로만 판단.

### 3.5 연결 검증 정보를 지역 스냅샷에 보존

추출할 때는 경로가 아직 정해지지 않았고, 나중에 다른 경로를 고르거나 전국 세대를 지울 수 있다. 그래서 대조는 **경로 노드만이 아니라
스냅샷의 모든 노드**에 대해 추출 시점에 한 번 하고, 결과를 스냅샷 세대 안에 저장한다. 이후 확인에는 전국 파일이 필요 없다.

- 파일: 세대 폴더의 `connectivity.json`(형식 이름 `connectivity-v1`). 해시는 `meta.toml`에 기록한다(§4.6).
- 내용:
  - `rule_version`: 추출 규칙 버전(§3.1·§3.2 규칙이 바뀌면 올림).
  - `graph_sha256`: 대조한 본문(`graph.osm.json`)의 해시.
  - `allowed_highways`: 대조에 쓴 허용 도로 종류(정렬한 목록). 연결 완전성은 어떤 도로 종류를 포함했는지에 따라 달라지므로
    전국 차수·이웃도 **이 목록 기준으로만** 센다.
  - `checked_nodes`: 대조한 노드 수(= 스냅샷의 전체 노드 수). 맞지 않으면 파일을 거부.
  - `incomplete`: 전국 자료와 연결이 다른 노드 목록. 노드마다
    - `node`: 노드 ID
    - `national_degree`, `local_degree`
    - `missing`: 지역 스냅샷에 없는 연결 `[way ID, 이웃 노드 ID]` 목록(전국 자료 기준)
  - 목록에 없는 노드는 "전국 자료와 연결이 같음"으로 판정된 노드다. 스냅샷의 모든 way는 노드를 전부 보존하므로(§3.1),
    불완전은 **영역 밖 way가 붙는 노드**에서만 생긴다.
- 크기를 줄이려고 전체 이웃 목록 대신 **불완전한 노드와 빠진 연결만** 저장한다. 전국 기준 이웃 목록 전체가 필요해지면
  G-2 측정 후 형식을 `connectivity-v2`로 올린다.

이후 사용(경로 계획 `plan_route_detailed`, 저장 경로 재생 `load_route_course`, 교차로 생성 모두):

- 불완전 노드 집합을 I라 할 때, 다음 중 하나라도 해당하면 **거부**한다.
  1. 경로가 I의 노드를 지난다.
  2. 경로의 교차로 노드가 I에 속한다.
  3. 경로의 교차로에서 팔·곁가지를 따라가며 형상에 쓰는 거리(곁가지 길이 등 현재 교차로 설정) 안에서 I의 노드를 만난다.
- 거부 메시지에는 노드 ID와 빠진 연결(way ID)을 보여 준다.
- 저장된 경로를 다시 열 때도 같은 검사를 한다. 같은 스냅샷 세대·같은 `connectivity.json`이므로 결과도 같다.
  재생 경로는 이 검사를 **건너뛰는 분기를 두지 않는다**(경로 계획과 재생이 같은 검사 함수를 거친다).
- **연결 정보와 사용 설정의 결속:** 사용할 때마다 다음이 모두 맞는지 확인한다.
  1. `connectivity.json`의 `graph_sha256` = 실제 본문 해시 = `meta.toml`의 `graph_sha256`
  2. `rule_version`이 프로그램이 아는 버전
  3. 지금 쓰려는 허용 도로 목록(경로 계획은 `config/road_graph.toml`, 재생은 경로 파일의 `allowed_highways`)이
     `connectivity.json`의 `allowed_highways`와 **같음**
- 하나라도 맞지 않으면 그 스냅샷으로는 경로 계획·재생을 **거부**하고 이유를 보여 준다. 허용 도로 목록이 다를 때 할 수 있는 것은
  전국 세대가 남아 있으면 **새 설정으로 다시 추출해 새 세대를 만드는 것**(재검증)뿐이다. 기존 세대·연결 정보를 고쳐 쓰지 않는다.
  전국 세대가 없으면 거부로 끝난다.
  - 목록이 부분집합이면 괜찮다고 볼 수 있는지(도로 종류를 줄이면 연결이 끊긴 것처럼 보일 수 있음)는 판단하지 않고, 일단 **같음만 허용**한다.
- `connectivity.json`이 없거나 해시가 맞지 않거나 규칙 버전을 모르면, Geofabrik 출처 스냅샷은 **거부**한다.
- 기존 Overpass 스냅샷(연결 정보 없음)은 지금 동작을 유지하되 "연결 검증 정보 없음"으로 표시한다(§4.6 호환).
  Overpass 스냅샷에도 같은 검사를 요구할지는 별도로 정한다.

## 4. 파일 식별·무결성·버전 관리

### 4.1 두 가지를 구분한다

| 목적 | 방법 | 증명하는 것 | 증명하지 못하는 것 |
| --- | --- | --- | --- |
| **버전 식별** | 받은 파일에서 직접 계산한 해시(예: SHA-256 또는 MD5), PBF 머리부의 복제 시각·순번 | "어떤 파일인지" 구별, 저장 코스가 어느 원본에서 왔는지 기록 | 파일이 **제대로 받아졌는지**(잘린·손상된 파일도 해시는 나옴) |
| **다운로드 무결성** | §4.2의 검사들 | 전송이 끝까지 됐고, 제공자가 공개한 파일과 같으며, PBF로 읽힘 | — |

### 4.2 무결성 검사 단계

1. **전송 완료 검사:** HTTP 상태 200, `Content-Length`가 있으면 받은 바이트 수와 일치. 연결이 중간에 끊기면 실패.
2. **제공 체크섬 대조:**
   - Geofabrik는 날짜가 붙은 파일(`south-korea-YYMMDD.osm.pbf`)에 `.md5`를 제공한다. 목록에서 `latest` 파일의 `.md5`는 보지 못했다.
   - 따라서 기본안은 **날짜 붙은 파일과 그 `.md5`를 함께 받아 대조**하는 것이다. 어느 날짜 파일을 받을지 정하는 방법(디렉터리 목록 해석, `index-v1.json`, `state.txt` 등)은 G-3에서 확인한다.
   - 제공 체크섬을 얻지 못하면: **무결성 미확인**으로 표시하고, 사용자가 명시적으로 허용할 때만 사용한다(기본은 거부).
3. **PBF 파싱 검사:** 머리부 블록을 읽고, 모든 블록을 끝까지 압축 해제·해석할 수 있어야 한다. 실패하면 거부.
4. **머리부 정보 처리:**
   - 복제 시각(`osmosis_replication_timestamp`)·순번이 있으면 세대 메타에 기록.
   - **없으면:** 파일 자체는 거부하지 않되, 버전 식별은 파일 해시 + 받은 시각 + 원본 URL로 하고, 메타에 "머리부 시각 없음"을 기록한다.
     데이터 시각을 화면에 보여 줄 때도 "미확인"으로 표시한다.
   - 머리부의 범위(bbox)가 한국 범위와 크게 다르면 거부.

### 4.3 저장과 실패 시 보존

- `.part` 파일로 받는다 → §4.2 검사 → 인덱스 생성(G-2 이후) → 모두 성공했을 때만 세대 폴더로 옮기고 `latest.toml`을 바꾼다.
- 어느 단계에서 실패해도 **기존 세대는 그대로**다. 실패한 `.part`는 다음 시도 때 지운다(사용자 파일이 아니라 앱이 만든 임시 파일).
- 세대 폴더: `cache/geofabrik/south-korea/<UTC 시각>-<해시 앞자리>/{source.osm.pbf, meta.toml, index/...}`.

### 4.4 저장 코스의 재현

- 저장한 경로 파일(`route-v1`)은 지금처럼 **지역 스냅샷 세대**를 가리킨다.
- 지역 스냅샷 `meta.toml`에 출처(`geofabrik` / `overpass`), 원본 PBF의 해시·머리부 시각·URL, 추출 규칙 버전, 여유 폭 m을 기록한다.
- Geofabrik는 오래된 날짜 파일을 "after a while" 삭제한다고 안내한다. 그래서 전국 파일을 다시 받을 수 없어도
  **작은 지역 스냅샷만으로 같은 코스를 다시 만들 수 있게** 지역 스냅샷을 불변으로 보존한다. 전국 세대를 지워도 저장 코스는 재생된다.

### 4.5 갱신

- 매일 갱신되지만 **자동으로 받지 않는다.** 사용자가 요청할 때만 받는다.
- 변경분(`.osc.gz`) 적용 갱신은 이번 범위에서 제외한다.

### 4.6 지역 스냅샷 메타데이터 형식과 호환

현재 `map_fetch::SnapshotMeta`(`meta.toml`)는 Overpass 전용 필드(`query`, `endpoint`, `timestamp_osm_base` 등)를 필수로 두고
`deny_unknown_fields`로 읽는다. 또 `load_generation`은 본문에 Overpass 응답 검사(`check_response`, `osm3s` 머리부)를 한다.
Geofabrik 추출 결과는 Overpass 응답이 아니므로 그대로 넣을 수 없다.

**새 형식 `snapshot-meta-v2`** (Geofabrik 세대에 사용):

```toml
meta_format = "snapshot-meta-v2"
source = "geofabrik"            # "overpass" | "geofabrik"
bbox = { south = ..., west = ..., north = ..., east = ... }   # 사용자 영역
created_at = "2026-11-07T00:00:00Z"
graph_file = "graph.osm.json"
graph_sha256 = "..."
graph_bytes = 123456

[geofabrik]
pbf_url = "https://download.geofabrik.de/asia/south-korea-YYMMDD.osm.pbf"   # G-1 로컬 파일이면 생략하고 pbf_file_name만 기록
pbf_sha256 = "..."               # 버전 식별(§4.1)
pbf_md5_provided = "..."         # 제공 체크섬. 없으면 생략하고 integrity = "unverified"
integrity = "verified"           # "verified" | "unverified"(사용자 허용, §4.2)
replication_timestamp = "..."    # PBF 머리부. 없으면 생략하고 data_time = "unknown"
replication_sequence = 0         # 머리부에 있을 때만
extract_rule_version = 1
margin_m = 150.0                 # §3.1 여유 폭
allowed_highways = [...]          # 추출에 쓴 허용 도로 종류

[connectivity]
file = "connectivity.json"
format = "connectivity-v1"
sha256 = "..."
checked_nodes = 12345
incomplete_nodes = 3
```

- 본문(`graph.osm.json`)은 `parse_overpass_graph`가 읽는 요소 구조(`elements[].type/id/nodes/geometry/tags`)로 쓴다.
  다만 Overpass `osm3s` 머리부는 **만들어 넣지 않는다**(출처를 속이지 않기 위함). 대신 `generator = "self-driving-sim geofabrik-extract v1"`를 둔다.
- 해시는 Geofabrik 세대에서 SHA-256을 쓴다(새 의존성 여부는 G-1에서 확인, 지금 세대 이름의 FNV-64는 식별용으로 유지).

**호환 규칙:**

- 읽기: `meta_format`이 없으면 **기존 형식(v1, Overpass)**으로 보고 지금 구조체로 읽는다. `snapshot-meta-v2`면 새 구조체로 읽는다. 그 밖의 값은 거부.
- 본문 검사는 출처에 따라 나눈다. Overpass → 지금의 `check_response` + 바이트 수. Geofabrik → `graph_sha256`·`graph_bytes`·`connectivity` 해시 대조 + 요소 구조 검사.
- 기존 Overpass 세대는 불변이므로 **다시 쓰지 않는다.** 새 Overpass 세대도 G-1~G-3에서는 지금 v1으로 쓴다(바꿀 필요가 생기면 별도 단계).
- 경로 파일(`route-v1`)은 바꾸지 않는다. 스냅샷 경로가 불변 세대를 가리키므로 출처·해시·연결 정보는 세대의 `meta.toml`에서 얻는다.
- 같은 bbox에 Overpass·Geofabrik 세대가 섞일 수 있다. `latest.toml`은 지금처럼 최신 세대 하나를 가리키고, 출처 선택(G-4)이 생기면 출처별 포인터로 나눌지 정한다.

## 5. Overpass와의 관계, 지원 조건

### 5.1 병행

- **병행을 추천한다.** 검증이 끝나면 Geofabrik를 기본으로 쓰고, Overpass는 전국 파일이 없거나 최신 자료가 필요한 작은 지역에 쓰는 보조 수단으로 둔다.
- 두 출처 모두 같은 세대 구조(`graph.osm.json` + `meta.toml`, Geofabrik은 `connectivity.json` 추가)로 저장해 그 뒤 처리를 같게 한다. 메타 형식 차이는 §4.6.
- `--offline`과 자동 시험의 외부 요청 금지는 유지한다. 자동 시험은 저장소에 둔 작은 시험 자료만 쓴다.

### 5.2 지원·거부 조건 유지

- 허용 도로 종류와 최소 폭 규칙
- 한국 범위(위도 33.0–38.7, 경도 124.5–132.0)
- 경로 범위 1500 × 1500 m, 스냅 100 m, 경로 길이 2000 m 상한
- 교차로 형상 검사(4-2)
- 추가: §3.2 경계 연결 검증 실패 시 거부

## 6. ODbL 출처 표기와 배포 조건

Geofabrik 다운로드 페이지 문구: "licensed under the Open Database License 1.0 … you have to acknowledge OpenStreetMap as the data source. Derived databases have to retain the same license."

- 화면: 경로 선택·주행 화면에 "© OpenStreetMap contributors"와 ODbL 링크 표시(현재 방식 유지).
- 파생 데이터베이스(인덱스, 지역 스냅샷)를 배포할 때는 ODbL을 유지하고 출처를 표기한다.
- 전국 PBF와 인덱스는 git에 올리지 않는다. 저장소에 넣는 시험 자료는 출처·라이선스 문구를 함께 둔다.
- 공개 파일에는 `user`·`uid`·`changeset`이 없다("missing … since May 3, 2018").
- 다운로드 예절: 확인한 페이지에는 요청 제한이나 User-Agent 규정이 없었다. 그래도 일반 UA `self-driving-sim-dev/0.1`, 한 번에 하나, 사용자 요청 시에만 받는다.
- 이 절은 공개 문구 요약이며 법률 검토가 아니다.

| 단계 | 내용 | 검증 |

| **G-2** | 전국 인덱스(§2.3 A/B 비교 후 결정)와 영역 조회 | 인덱스 조회 결과 = 전체 읽기 결과, 전국 이웃 대조 결과 일치, 크기·조회 시간 측정 |
| **G-3** | 받기·갱신: 전송 완료, 제공 체크섬, 파싱, 머리부 처리(§4.2), 세대·실패 보존(§4.3) | 잘린 파일·체크섬 불일치·파싱 실패·머리부 없음·중단 회귀. 네트워크 없는 시험용 전송 사용 |
| **G-4** | 경로 선택 화면 연동: 출처 선택, 진행 표시, Overpass 대체, 출처 표기 | 자동 시험 + 사람이 직접 한 확인 기록(클릭·영역 선택·경로·주행 전환) |

G-1 검증 항목:

- **§7.3 정답 fixture 대조(추출 정확성).** 사람이 기대값을 명시한 작은 PBF로 확인한다.
- §7.4 실제 여수 추출에 대한 보존 규칙 대조.
- §7.1 재현성 검사 중 G-1에서 가능한 것(같은 PBF로 두 번 추출한 결과의 일치).
- §7.2 날짜가 다른 자료 비교(기존 여수 Overpass 스냅샷과).
- 영역을 가로지르는 way(양 끝 노드가 영역 밖)가 포함되는지(§7.3 사례로도 확인).
- 경계 연결 검증: 정상 지역은 통과, 여유 폭을 일부러 줄인 경우는 거부되는지. `connectivity.json`만으로(전국 파일 없이) 같은 거부 결과가 나오는지.
- 메타 v1(기존 Overpass 세대)·v2(Geofabrik 세대) 모두 읽히는지, 해시가 틀린 v2 세대는 거부되는지.
- 코스 생성·시험 주행 회귀.
- **최대 메모리, 단계별 시간, 지역 스냅샷 크기 측정·기록.**

### 7.0 판정 기준: 재현성과 정확성을 나눈다

| 검사 | 보여 주는 것 | 보여 주지 못하는 것 |
| --- | --- | --- |
| §7.1 재현성·구현 간 일관성 | 같은 입력에서 같은 결과가 나옴, 전체 읽기와 인덱스 추출이 서로 같음 | 결과가 **옳은지**. 같은 구현이 같은 누락(예: 교차 선분 누락, 연결 누락)을 매번 반복해도 일치한다. 두 경로가 같은 잘못된 공통 함수를 써도 일치한다 |
| §7.3 정답 fixture 대조 | 사람이 독립적으로 정한 기대값과 같은지 = **추출 정확성** | fixture에 없는 사례 |
| §7.4 보존 규칙 대조 | 실제 자료에서 §3.1·§3.2 규칙이 지켜졌는지 | 규칙 자체가 맞는지 |
| §7.2 날짜가 다른 자료 비교 | 기존 자료와 차이의 원인 분류 | 정확성(차이가 설명되지 않아도 결함으로 단정하지 않음) |

**추출 결함으로 판정하는 경우:**

1. §7.3 정답 fixture의 기대값과 다름
2. §7.4 보존 규칙 위반(같은 원본에서도)
3. §7.1 반복·구현 간 결과 불일치

이 셋 중 어느 하나라도 해당하면 결함이다. §7.1 일치는 필요조건일 뿐 정확성의 증명이 아니다.

### 7.1 같은 원본 비교: 재현성·구현 간 일관성

같은 PBF(같은 `pbf_sha256`)와 같은 영역·여유 폭·규칙 버전·허용 도로 목록으로 만든 결과끼리는 **결정적으로 같아야** 한다.
다르면 추출 결함이다(§7.0의 3). 다만 일치한다고 추출이 옳다는 뜻은 아니다(§7.3·§7.4로 확인).

| 비교 | 시점 | 일치해야 하는 것 |
| --- | --- | --- |
| 같은 방법으로 두 번 추출 | G-1 | `graph.osm.json`·`connectivity.json` 바이트, 각 해시 |
| 전체 읽기 추출 vs 인덱스 추출 | G-2 | `graph.osm.json`·`connectivity.json` 바이트 |
| 위 스냅샷으로 만든 경로·코스 | G-1, G-2 | 같은 찍은 점에서 경로 노드 순서, 교차로 목록, 폭, 코스 형상(충돌체·외곽선) |
| `meta.toml` | G-1, G-2 | 아래 "비교 제외 필드"를 뺀 나머지 필드 값 |

**정렬·직렬화 규칙** (바이트 일치를 위해 고정):

- `graph.osm.json`: way를 way ID 오름차순으로. way 안의 노드는 OSM 원래 순서 그대로(정렬하지 않음). 태그는 키 오름차순(`BTreeMap`).
  좌표는 PBF 정수값(1e-7°)을 십진 고정 소수 7자리로 쓴다(부동소수 출력 차이 방지). 공백 없는 한 줄 JSON, 끝에 줄바꿈 하나, UTF-8.
- `connectivity.json`: `incomplete`를 노드 ID 오름차순, `missing`을 (way ID, 이웃 노드 ID) 오름차순. 같은 직렬화 규칙.
- 병렬 읽기를 쓰더라도 결과를 위 순서로 정렬한 뒤 쓴다(블록 처리 순서에 의존하지 않음).

**비교 제외 필드** (`meta.toml`, 실행마다 달라질 수 있음):

- `created_at`(만든 시각), 세대 폴더 이름(시각이 들어감)
- 실행별 경로(입력 PBF의 로컬 경로 등). 메타에는 로컬 절대 경로를 쓰지 않고, 필요하면 파일 이름만 기록한다.
- 그 밖의 필드(출처, PBF 해시, 규칙 버전, 여유 폭, 허용 도로 목록, 본문·연결 정보 해시, 노드 수 등)는 비교한다.

### 7.2 날짜가 다른 자료 비교: 차이 원인 조사

기존 여수 Overpass 스냅샷은 Geofabrik 파일보다 이전 시각(`timestamp_osm_base`)의 자료다. 그사이 OSM 편집이 있었다면 노드 순서·교차로가
달라질 수 있으므로 일치를 요구하지 않는다. 대신 **모든 차이를 원인별로 분류**한다.

비교 전 맞출 것: Overpass와 같은 영역(여유 폭 0)으로도 한 번 추출해, 여유 폭 때문에 생긴 차이와 섞이지 않게 한다.

**분류는 세 가지다.**

- **정상 변경(확인됨):** 차이를 만든 OSM 편집이 직접 확인됨(편집 이력에서 이전 버전이 Overpass 쪽 내용, 이후 버전이 Geofabrik 쪽 내용과 같음).
  편집 이력 조회는 네트워크를 쓰므로 사용자 요청이 있을 때만 한다.
- **규칙 차이(확인됨):** 선분만 영역을 지나는 way(§3.1)처럼 추출 규칙이 Overpass와 달라 생긴 차이. 그 way의 노드가 영역 안에 하나도 없고
  선분이 영역과 교차함을 좌표로 직접 확인한 경우에만 이 분류로 둔다. 따로 집계한다.
- **데이터 동등성 미확인:** 위 두 확인이 없는 차이 전부. **추출 코드 결함으로 단정하지 않고** 목록으로 남겨 원인을 더 조사한다.
  아래 "시각 근거"가 있는 항목은 이 안에서 "변경 가능성 있음"으로 표시해 조사 순서를 정하는 데 쓴다.
  추출 결함 여부는 §7.0의 판정(정답 fixture, 보존 규칙, 재현성)으로 따로 정한다.

**수정 시각은 변경 가능성을 보여 줄 뿐 차이를 설명하지 않는다.** 노드 좌표가 바뀌어도 그 노드를 참조하는 way의 수정 시각·버전은
그대로일 수 있다. 그래서 way와 **참조 노드의 변경을 함께** 확인한다. 아래 표의 시각 근거는 **어느 것도 정상 변경을 확정하지 않으며**,
동등성 미확인 항목에 "변경 가능성 있음" 표시를 붙이는 조건일 뿐이다.

| 차이 | "변경 가능성 있음" 표시 조건(시각 근거) | 함께 확인할 것 |
| --- | --- | --- |
| Overpass에만 있는 way | 전국 PBF에서 그 way가 허용 도로가 아니게 됐고 way 버전 시각이 기준 시각 이후. **전국 PBF에 way가 없다는 사실만으로 삭제를 확정하지 않는다**(삭제·영역 밖 이동·추출 누락을 구별할 근거가 없으면 표시 없이 미확인) | 같은 ID가 전국 PBF에 있는지, 있다면 영역과의 관계(§7.4) |
| Geofabrik에만 있는 way | way 버전 시각이 기준 시각 이후 | 규칙 차이(위)에 해당하는지 먼저 확인 |
| 같은 way ID, 태그 다름 | way 버전 시각이 기준 시각 이후 | — |
| 같은 way ID, 노드 목록 다름 | way 버전 시각이 기준 시각 이후 | 추가·삭제된 노드의 존재·좌표 |
| 같은 노드 ID, 좌표 다름 | **그 노드**의 버전 시각이 기준 시각 이후. way의 시각은 쓰지 않음 | 그 노드를 참조하는 way 목록 |
| 경로 노드 순서·교차로 차이 | 원인이 되는 자료 차이가 모두 "변경 가능성 있음" 또는 확인된 분류 | 어느 자료 차이가 원인인지 추적 |

- 근거 자료는 PBF 요소의 `timestamp`·`version`이다. Geofabrik 공개 파일에 이 값이 들어 있는지는 **미확인**이다
  (user·uid·changeset만 뺐다고 안내함). 없으면 위 근거를 쓸 수 없으므로 해당 차이는 모두 **데이터 동등성 미확인**으로 기록한다.
- Overpass 스냅샷(`out body`)에는 요소 버전이 없으므로, "기준 시각 이후 변경"은 Geofabrik 쪽 시각과 Overpass `timestamp_osm_base`의 비교로만 판단한다.
  그 사이 여러 번 편집됐을 수도 있으므로 이 비교는 변경이 있었다는 근거일 뿐 무엇이 바뀌었는지까지 보여 주지 않는다.
- OSM 편집 이력 조회(네트워크 사용)는 사용자 요청이 있을 때만 한다.
- 좌표 비교는 PBF 정밀도(1e-7°)로 반올림한 값으로 한다.
- 결과는 분류별 개수와 목록을 문서(`docs/map-data.md`의 G-1 절)에 기록한다. 동등성 미확인 항목이 있어도 G-1을 실패로 처리하지 않고,
  남은 항목과 조사 상태를 그대로 적는다.
- 기존 여수 Overpass 스냅샷과 그것으로 만든 시험(교차로 4곳 등)은 **그대로 둔다.** Geofabrik 기반 시험 자료는 별도 파일로 추가하고,
  기대값은 §7.3처럼 사람이 정한 정답으로 둔다(추출 함수 출력에서 자동 생성하지 않음).

### 7.3 정답 fixture 대조 (G-1부터)

- 시험 코드 안에 작은 PBF fixture를 둔다(만드는 방법은 §8 미확인: 시험용 PBF 작성기 필요 가능성).
- 각 사례의 **기대값을 사람이 직접 적는다**: 선택돼야 할 way ID, 보존돼야 할 노드 ID·좌표, `connectivity.json`의 불완전 노드·빠진 연결,
  경로·교차로 생성의 통과/거부 결과와 거부 이유. **기대값을 현재 추출 함수의 출력에서 자동 생성하거나 덮어쓰지 않는다.**
- 사례(최소):

| 사례 | 기대 |
| --- | --- |
| 노드 하나가 영역 안인 way | 선택, 노드 전부 보존 |
| 양 끝 노드가 영역 밖이고 선분만 영역을 지나는 way | 선택, 노드 전부 보존 |
| 영역 R 근처지만 노드도 선분도 R과 겹치지 않는 way | 선택 안 함(단, 선택 way와 노드를 공유하면 그 노드는 `incomplete`) |
| 선택 way가 참조하는 영역 밖 노드 | 좌표 포함 보존 |
| 영역 밖 way가 경계 노드에 붙음 | 그 노드가 `incomplete`, `missing`에 (way ID, 이웃 노드 ID) |
| 차수는 같지만 이웃이 다른 노드(지역 쪽 연결이 다른 way로 대체된 것처럼 꾸민 경우) | 이웃 ID 대조로 `incomplete` |
| 허용되지 않은 `highway`(예: `footway`)가 붙은 노드 | 허용 목록 기준이므로 불완전으로 세지 않음 |
| 위 불완전 노드를 지나는 경로·교차로 팔 | 경로 계획·재생 모두 거부, 이유에 노드·way ID |
| 허용 도로 목록을 바꿔 재생 | 거부(§3.5 결속) |
| 좌표 누락 노드, 노드 1개 way | 오류 |

### 7.4 보존 규칙 대조 (실제 여수 추출, G-1부터)

정답을 손으로 적을 수 없는 실제 자료에서는 결과가 §3.1·§3.2 규칙을 지키는지 전국 자료와 대조한다.

- 전국 허용 도로 중 영역과 노드 포함 또는 선분 교차하는 way가 **모두** 스냅샷에 있음, 그렇지 않은 way는 없음.
- 스냅샷 way의 노드 ID 목록·순서·태그·좌표가 전국 PBF의 해당 way와 같음(영역 밖 노드 포함).
- `connectivity.json`의 불완전 노드 = 전국 기준 이웃 집합 ≠ 지역 기준 이웃 집합인 노드, 정확히 일치.
- 대조 코드는 추출 코드의 선택·대조 함수를 **재사용하지 않고** 단순한 전수 검사로 따로 쓴다(같은 함수의 같은 누락을 반복하지 않도록).
  기하 판정(선분-사각형 교차)도 별도의 단순 구현을 쓴다. 이 대조가 추출과 같은 잘못된 가정을 공유할 가능성은 남으므로, 정확성의 주 근거는 §7.3이다.

예상 규모(대략): G-1 새 모듈 하나 400~700줄, G-2 500줄 안팎, G-3 300줄 안팎, G-4 300줄 안팎. 측정 결과에 따라 달라질 수 있다.

메뉴(4-5a)·배경 지도(4-5b)와의 순서: G-1은 CLI와 모듈 하나라 서로 영향이 없다. 순서는 사용자가 정한다.

## 8. 미확인 사항

- 시험용 작은 PBF를 만드는 방법(`osmpbf`는 읽기 전용이므로 시험 코드 안의 간단한 작성기가 필요할 수 있음).
- Geofabrik 파일이 종류별·ID순으로 정렬되어 있는지(두 번 읽기 최적화 가능 여부).
- 한국 허용 도로 way·노드 수, 최대 메모리, 인덱스 크기.
- 날짜 붙은 파일과 `.md5`를 안정적으로 찾는 방법, `latest` 파일의 체크섬 제공 여부.
- Overpass `way(bbox)`가 가로지르는 way를 포함하는지.
- Geofabrik 공개 PBF에 요소별 `timestamp`·`version`이 들어 있는지(§7.2 분류에 필요).
- SHA-256 계산에 새 의존성이 필요한지.
- Overpass 스냅샷에도 연결 검증(§3.5)을 요구할지.
- Geofabrik imprint와 다운로드 서버 이용 조건, `osmpbfreader` 라이선스.
