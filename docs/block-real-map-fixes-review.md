# 실제 블록 지도 수정과 오늘 검증 범위

## 결과와 범위

작업 브랜치는 `feature/block-real-map-fixes`, 선행 UI 브랜치 `feature/block-route-picker`의 7f64e58 위에서 시작했다. main/develop은 96c04ec로 유지한다. 이 후속 작업은 main/develop 병합·push·GitHub 릴리스 갱신을 하지 않는다. 사용자의 오늘 우선 요청에 따라 원본 OSM 세 고정 표본을 재현 가능한 검토 범위로 삼았다.

| 표본 | 원본 선택 | 경로 길이 |
| --- | --- | --- |
| 엑스포 내부 주차 통로 | way 532526365, 13388325415→8664556115 한 블록을 출발·도착에 지정 | 98.2 m |
| 엑스포 주변 곡선 접속 | way 1286142779, 772406248→794175423 출발, 794175423→12468412566 도착 | 1,016.3 m |

출처와 발췌 범위는 testdata/block-real/README.md에 원본 캐시 SHA-256·way 집합과 함께 기록했다. 전체 지역이나 현장 실측 지도가 아니다. 강남 작업 표본은 via 주변 30 m에 걸치는 3개 way 전체를 보존한 범위이며, 원본 관계의 진출 way가 범위 밖이어도 해당 진입 관계는 지우지 않았다.

## 고친 원인

- 기존 접속부는 절단 전 구간이 직선이어야 했고, 곡선 입구를 원래 접선의 직선 단면으로 가정했다. 실제 절단 위치의 방위로 절단 길이를 반복 계산하고, 국소 접선과 도로 띠 양 끝에 맞춰 입구·경계·연석을 연결한다.
- 지도 절대 좌표에서 작은 원호를 생성하면 부동소수점 상쇄로 부채꼴 판정이 흔들렸다. 접속 노드 원점에서 생성한 뒤 지도 좌표로 옮긴다. 실제 표본의 원점을 ±800 m 이동하는 회귀도 추가했다.
- 곡선 입구 때문에 오목해진 다각형을 하나의 중심 부채꼴로 강제하지 않는다. 외곽은 유지하고 삼각분할한 면들을 CourseDef에 보낸다. 비인접 경계의 실제 교차·접촉, 뒤집힌/퇴화 삼각형, 면적 불일치 및 불완전 분할은 계속 거부한다.
- 강남 관계 7365613은 via가 진입 way에는 있고 진출 way에는 없는 원본 참조 불일치다. 관계와 원본 도로는 보존하고 해당 진입 연결을 닫고 경고한다. via 위치 자체가 불명인 관계 7383523 같은 경우 해당 진입 way의 모든 출구를 닫으며, 양 끝을 다른 way와 합쳐 이 차단을 우회하지 못하게 한다. 없는 진입 way나 좌표 모순은 여전히 오류다.
- 관계를 추측해 이동하거나 제한을 삭제하지 않는다. 경로 계획 후 형상 실패 때문에 다른 경로를 자동 탐색하지도 않는다. 격리 진단은 UI와 저장 후 CourseDef.notices에 보존된다.

## 검증 근거

1. 구현 전 합성 곡선 단면과 불완전 회전 관계 시험의 실패를 확인했다.
2. 별도 detached test 워크트리에서 fmt/clippy(경고 0), Rust 468개(core 449 + 통합 4 + Godot 12 + CLI 3), Godot 26종 통과.
3. 실제 표본은 도로와 방향을 고정했다. 실패하면 다른 블록으로 재시도하는 시험이 아니다. 준비→새 TOML 저장→다시 읽기에서 코스·안내선·통과 순서 전체의 동일성을 검사한다.
4. 재생된 코스에 실제 운동·충돌 모델을 적용해 세 표본을 각 3/8 m/s로 추종했다. 모두 충돌 0·공통 RouteDriveEvaluator의 목표 도달 판정을 통과했다. 예전 끝 12 m 정지 규칙을 목표 도달로 보고하지 않는다. 목표 자세가 도로 끝보다 안쪽이고 판정 반경이 5 m이므로 결과의 도로 끝 잔여 길이는 약 13.5 m일 수 있다.
5. 최대 후륜축 안내선 오차: 내부 0.048 m, 주변 곡선 0.051 m, 강남 3 m/s에서 0.215 m·8 m/s에서 1.598 m 미만. 이는 시험용 추종기 결과이며 사람/실차 검증이 아니다.
6. Godot에서 세 표본을 실제 후보 상자로 확정하고 저장·재생 및 SimVehicle 준비/이동을 확인했다. Godot 자동 시험 자체는 128틱 이동 검사이며, 전체 경로 목표 도달은 위 Rust 운동/충돌/평가기 시험으로 검증했다.
7. 패키징 안전성 102개와 새 release 바이너리로 만든 독립 번들의 CLI+Godot 7개 검사 통과. 개발 PC와 다른 별도 PC에서의 수동 실행은 아직 하지 않았다.

## 실행과 수동 확인

검토 EXE: `../self-driving_sim-test/dist/block-real-review/Simulator.exe`. 전체 폴더를 유지한다. release_version=0이고 자동 업데이트는 꺼져 있어 공식 sim-v1로 바뀌지 않는다.

또는 develop/test 워크트리의 godot/project.godot에서 F5로 실행한다. 메뉴 → 경로 지도 → **엑스포 내부 실제 표본**을 누른다. 도로를 클릭하고 북쪽 방향(13388325415→8664556115)을 골라 출발로 확정한다. 같은 후보를 도착으로도 확정하고 경로 미리보기 → 주행 시작을 누른다. 전체 한 블록을 통과하는 약 98 m 코스다.

다른 표본을 보려면 **새 경로** 후 해당 실제 표본 버튼을 누르고 위 표의 방향을 지정한다. 고급 메뉴에서 저장 이름을 입력해 저장할 수도 있다. 저장 파일은 기존 메뉴의 저장 경로 목록에 보인다.

## 남은 범위와 호환성

- 원래 보고된 곡선/참조 문제는 위 표본과 원본 강남 관계 보존 시험으로 검증했다. 전체 1.5 km 지역을 다시 연 결과 엑스포/강남 모두 블록 구성은 가능하다. 그러나 전체 노면 생성은 별도 문제로 엑스포 node 806285558의 `block too short for joint cut`, 강남 node 414684605의 `curved joint boundary self-intersects`에서 거부된다. 이 도로들을 자동 삭제하거나 전체 자유 경로 성공으로 처리하지 않는다.
- 전체 10 km 지역·임의 모든 경로·실측 도로 폭·새 buildings/지형 기능은 오늘 검증 범위가 아니다. 범위 확대와 새 거부 원인 처리가 다음 작업이다.
- 블록 규칙 판본은 osm-road-blocks-v2, 도로망 판본은 road-network-v3다. 예전 판본의 블록 파일은 결과를 묵시적으로 바꾸지 않고 오류를 내며 명시적으로 다시 생성해야 한다. route-v1은 유지한다.
- main/develop 및 기존 미커밋 파일·.env·서명 키는 보존했다. 테스트 import가 만든 기존 변경도 임의로 커밋하지 않는다.
